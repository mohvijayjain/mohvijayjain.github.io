ScholarRAG: measuring what a RAG system gets right

A question-answering assistant for research papers, built with an evaluation framework from day one: retrieval and answer quality are scored separately on a hand-written question set.

The problem

Asking an LLM about papers gets you confident answers with no way to check them. I wanted answers grounded only in the uploaded PDFs, with the paper, section and page for every claim, and numbers that show how often retrieval and generation actually work.

How it works

  1. IngestPDFs parsed to Markdown with PyMuPDF4LLM. References, acknowledgements and appendices are cut before chunking, and the last heading is carried across pages so every chunk knows its section.
  2. Chunk & indexRecursive splitting on Markdown headings (1,000 chars, 300 overlap), embedded with BAAI/bge-small-en-v1.5 into ChromaDB.
  3. Hybrid retrieveEnsemble of vector search (MMR, k=15) and BM25 (k=15), weighted 60 / 40, filtered to the documents the user selects.
  4. RerankBAAI/bge-reranker-base cross-encoder keeps the top 4 chunks.
  5. GenerateLlama 3.1 70B on NVIDIA NIM (temperature 0.2) answers only from those chunks, cites paper and section, and says it could not find the answer when the context doesn't contain it.

Evaluation

I wrote 100 questions with reference answers across 19 ML/RAG papers (Attention, BERT, DPR, RAG, LoRA, Self-RAG, ReAct and others), tagged by type: concept, architecture, implementation, comparison and evaluation. RAGAS scores them with Llama 3.1 70B as the judge.

Engineering decisions

  • Section-aware metadata. Carrying headings across page breaks is what makes "paper + section + page" citations possible.
  • Cleaning before chunking. Dropping reference lists removed a big source of noisy, citation-only matches.
  • Per-document filters on both retrievers. The hybrid retriever is rebuilt with matching Chroma and BM25 filters, falling back to vector-only when BM25 has nothing to match.
  • Built for rate limits. Exponential backoff, batched evaluation with cooldowns, resumable runs and a failed-question log kept a 100-question eval running on a free API tier.

API

POST /upload ingest a PDF · GET /documents list indexed papers · POST /chat ask a question, returns answer + sources. A Streamlit UI sits on top.
